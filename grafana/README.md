# Grafana and Prometheus files

What the main-LAN unit's metrics look like once something scrapes them.
Nothing here runs on a unit; it is for the monitoring host.

| File | What it is | How to load it |
|---|---|---|
| `rules/mother-ticker.rules.yml` | Alert rules, Prometheus rule format | Prometheus `rule_files:`; a Mimir or Thanos ruler; or Grafana 11.4+ Alerting, Alert rules, *Import to Grafana-managed rules* |
| `dashboards/mother-ticker.json` | The dashboard, generated by `scripts/gen_grafana_dashboard.py` | Dashboards, New, Import, upload the file and pick your Prometheus datasource; or provision it with the file below |
| `provisioning/dashboards/mother-ticker.yaml` | Dashboard provisioning | Copy to `/etc/grafana/provisioning/dashboards/` and the JSON to `/var/lib/grafana/dashboards/mother-ticker/` |

The dashboard reads its datasource from its own `Prometheus` variable, so
both the import dialogue and file provisioning work without editing the JSON.
`Site` and `Unit` variables come from the `site` and `instance` labels, so
several units share one board.

## Scrape config

```yaml
scrape_configs:
  - job_name: mother-ticker
    static_configs:
      - targets: ["ntp-main:9101"]
```

The job name matters: `MotherTickerScrapeDown` is written against
`up{job="mother-ticker"}`. The unit's nftables rules only admit the scraper
addresses listed in `mother_ticker_metrics_allow`, so the first thing to
check when `up` is 0 is that list.

## The rules

`docs/alerts.md` lists every rule with its threshold and what to do when it
fires. The durations are deliberate: PPS takes minutes to be trusted after a
cold start, and the unit's own health ladder handles anything shorter than
the `for` values here. If you tune one, tune it in the file; the test suite
checks that every metric a rule names is one the exporter serves and that
`docs/alerts.md` names the same rules.

## Regenerating the dashboard

```sh
python3 scripts/gen_grafana_dashboard.py           # rewrite the JSON
python3 scripts/gen_grafana_dashboard.py --check   # what CI runs
```

Edit the generator, not the JSON: a panel is a title, a metric and a unit,
and the generator lays them out. Provisioning has `allowUiUpdates: false`
for the same reason.
